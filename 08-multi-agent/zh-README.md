# 多智能体设计模式

当你开始着手一个涉及多个智能体的项目时，你需要考虑多智能体设计模式。然而，何时转向使用多智能体以及其优势可能并不立即明确。

## 简介

在本课程中，我们将回答以下问题：

- 哪些场景适用于多智能体？
- 与单个智能体执行多项任务相比，使用多智能体有哪些优势？
- 实现多智能体设计模式的构建块是什么？
- 如何了解多个智能体之间的交互情况？

## 学习目标

完成本课程后，你应该能够：

- 识别适用于多智能体的场景
- 认识到使用多智能体相对于单个智能体的优势
- 理解实现多智能体设计模式的构建块

更大的图景是什么？

*多智能体是一种设计模式，允许多个智能体协同工作以实现共同目标*。

这种模式广泛应用于各种领域，包括机器人技术、自主系统和分布式计算。

## 适用于多智能体的场景

那么哪些场景适合使用多智能体呢？答案是，在许多场景中使用多个智能体是有益的，尤其是在以下情况下：

- **大量工作负载**：大量工作负载可以被分解为更小的任务并分配给不同的智能体，从而实现并行处理并更快完成。一个例子是大型数据处理任务。
- **复杂任务**：复杂任务（如大量工作负载）可以被分解为更小的子任务并分配给不同的智能体，每个智能体专门处理任务的特定方面。一个很好的例子是自动驾驶汽车，其中不同的智能体管理导航、障碍物检测和与其他车辆的通信。
- **多样化专业知识**：不同的智能体可以拥有不同的专业知识，使它们能够比单个智能体更有效地处理任务的不同方面。例如，在医疗保健领域，智能体可以管理诊断、治疗计划和患者监测。

## 使用多智能体相对于单个智能体的优势

单智能体系统可能适用于简单任务，但对于更复杂的任务，使用多个智能体可以提供几个优势：

- **专业化**：每个智能体可以专门处理特定任务。单个智能体缺乏专业化意味着它可以做所有事情，但在面对复杂任务时可能会混淆该做什么。例如，它可能最终执行一项它并不最适合的任务。
- **可扩展性**：通过添加更多智能体来扩展系统比让单个智能体过载更容易。
- **容错性**：如果一个智能体失败，其他智能体可以继续运行，确保系统可靠性。

让我们以用户预订旅行为例。单智能体系统需要处理旅行预订过程的所有方面，从查找航班到预订酒店和租车。要使用单个智能体实现这一点，该智能体需要具备处理所有这些任务的工具。这可能导致一个复杂且庞大的系统，难以维护和扩展。另一方面，多智能体系统可以有专门用于查找航班、预订酒店和租车的不同智能体。这将使系统更加模块化、易于维护和可扩展。

这可以比作作为夫妻店运营的旅行社与作为 franchise 运营的旅行社。夫妻店会有一个智能体处理旅行预订过程的所有方面，而 franchise 会有不同的智能体处理旅行预订过程的不同方面。

## 实现多智能体设计模式的构建块

在实现多智能体设计模式之前，你需要了解构成该模式的构建块。

让我们通过再次查看为用户预订旅行的例子来使其更加具体。在这种情况下，构建块将包括：

- **智能体通信**：用于查找航班、预订酒店和租车的智能体需要通信并共享有关用户偏好和约束的信息。你需要决定用于这种通信的协议和方法。具体来说，查找航班的智能体需要与预订酒店的智能体通信，以确保酒店预订的日期与航班日期相同。这意味着智能体需要共享有关用户旅行日期的信息，这意味着你需要决定 *哪些智能体在共享信息以及它们如何共享信息*。
- **协调机制**：智能体需要协调它们的行动，以确保满足用户的偏好和约束。用户偏好可能是希望酒店靠近机场，而约束可能是租车只能在机场获得。这意味着预订酒店的智能体需要与预订租车的智能体协调，以确保满足用户的偏好和约束。这意味着你需要决定 *智能体如何协调它们的行动*。
- **智能体架构**：智能体需要具有内部结构来做出决策并从与用户的交互中学习。这意味着查找航班的智能体需要具有内部结构来决定向用户推荐哪些航班。这意味着你需要决定 *智能体如何做出决策并从与用户的交互中学习*。智能体学习和改进的例子可能是，查找航班的智能体可以使用机器学习模型根据用户过去的偏好向用户推荐航班。
- **多智能体交互的可见性**：你需要了解多个智能体之间的交互情况。这意味着你需要有工具和技术来跟踪智能体的活动和交互。这可以采用日志记录和监控工具、可视化工具和性能指标的形式。
- **多智能体模式**：有不同的模式用于实现多智能体系统，如集中式、分散式和混合架构。你需要决定最适合你的用例的模式。
- **人工参与**：在大多数情况下，你会有人工参与，你需要指示智能体何时请求人工干预。这可能是用户要求智能体未推荐的特定酒店或航班，或者在预订航班或酒店之前要求确认。

## 多智能体交互的可见性

了解多个智能体之间的交互情况非常重要。这种可见性对于调试、优化和确保整个系统的有效性至关重要。为了实现这一点，你需要有工具和技术来跟踪智能体的活动和交互。这可以采用日志记录和监控工具、可视化工具和性能指标的形式。

例如，在为用户预订旅行的情况下，你可以有一个仪表板，显示每个智能体的状态、用户的偏好和约束以及智能体之间的交互。这个仪表板可以显示用户的旅行日期、航班智能体推荐的航班、酒店智能体推荐的酒店以及租车智能体推荐的租车。这将让你清楚地了解智能体之间的交互情况以及是否满足用户的偏好和约束。

让我们更详细地看看这些方面。

- **日志记录和监控工具**：你希望为智能体采取的每个行动进行日志记录。日志条目可以存储有关采取行动的智能体、采取的行动、采取行动的时间以及行动结果的信息。这些信息随后可用于调试、优化等。

- **可视化工具**：可视化工具可以帮助你以更直观的方式查看智能体之间的交互。例如，你可以有一个图表，显示智能体之间的信息流。这可以帮助你识别系统中的瓶颈、低效率和其他问题。

- **性能指标**：性能指标可以帮助你跟踪多智能体系统的有效性。例如，你可以跟踪完成任务所需的时间、每单位时间完成的任务数量以及智能体推荐的准确性。这些信息可以帮助你识别需要改进的领域并优化系统。

## 多智能体模式

让我们深入了解一些可用于创建多智能体应用程序的具体模式。以下是一些值得考虑的有趣模式：

### 群聊

当你想要创建一个多个智能体可以相互通信的群聊应用程序时，这种模式很有用。这种模式的典型用例包括团队协作、客户支持和社交网络。

在这种模式中，每个智能体代表群聊中的一个用户，智能体之间使用消息传递协议交换消息。智能体可以向群聊发送消息、从群聊接收消息以及响应其他智能体的消息。

这种模式可以使用集中式架构（所有消息都通过中央服务器路由）或分散式架构（消息直接交换）来实现。

![Group chat](./images/multi-agent-group-chat.png)

### 交接

当你想要创建一个多个智能体可以相互交接任务的应用程序时，这种模式很有用。

这种模式的典型用例包括客户支持、任务管理和工作流自动化。

在这种模式中，每个智能体代表一个任务或工作流中的一个步骤，智能体可以根据预定义的规则将任务交接给其他智能体。

![Hand off](./images/multi-agent-hand-off.png)

### 协同过滤

当你想要创建一个多个智能体可以协作向用户提供推荐的应用程序时，这种模式很有用。

你希望多个智能体协作的原因是每个智能体可以拥有不同的专业知识，并以不同的方式为推荐过程做出贡献。

让我们以用户想要获得关于股票市场上最佳股票购买的推荐为例。

- **行业专家**：一个智能体可以是特定行业的专家。
- **技术分析**：另一个智能体可以是技术分析专家。
- **基本面分析**：另一个智能体可以是基本面分析专家。通过协作，这些智能体可以向用户提供更全面的推荐。

## 场景：退款流程

考虑一个客户试图获得产品退款的场景，这个过程中可能涉及相当多的智能体，但让我们将其分为专门用于此过程的智能体和可用于其他过程的通用智能体。

**专门用于退款流程的智能体**：

以下是可能参与退款流程的一些智能体：

- **客户智能体**：这个智能体代表客户，负责启动退款流程。
- **卖家智能体**：这个智能体代表卖家，负责处理退款。
- **支付智能体**：这个智能体代表支付流程，负责向客户退款。
- **解决智能体**：这个智能体代表解决流程，负责解决退款过程中出现的任何问题。
- **合规智能体**：这个智能体代表合规流程，负责确保退款流程符合法规和政策。

**通用智能体**：

这些智能体可以被你的业务的其他部分使用。

- **运输智能体**：这个智能体代表运输流程，负责将产品运回给卖家。这个智能体可以同时用于退款流程和例如通过购买进行的产品一般运输。
- **反馈智能体**：这个智能体代表反馈流程，负责收集客户的反馈。反馈可以在任何时候进行，而不仅仅是在退款过程中。
- **升级智能体**：这个智能体代表升级流程，负责将问题升级到更高级别的支持。你可以在任何需要升级问题的流程中使用这种类型的智能体。
- **通知智能体**：这个智能体代表通知流程，负责在退款流程的各个阶段向客户发送通知。
- **分析智能体**：这个智能体代表分析流程，负责分析与退款流程相关的数据。
- **审计智能体**：这个智能体代表审计流程，负责审计退款流程以确保其正确执行。
- **报告智能体**：这个智能体代表报告流程，负责生成关于退款流程的报告。
- **知识智能体**：这个智能体代表知识流程，负责维护与退款流程相关的信息知识库。这个智能体可以同时了解退款和你的业务的其他部分。
- **安全智能体**：这个智能体代表安全流程，负责确保退款流程的安全性。
- **质量智能体**：这个智能体代表质量流程，负责确保退款流程的质量。

前面列出了相当多的智能体，包括专门用于退款流程的智能体和可用于业务其他部分的通用智能体。希望这能让你了解如何决定在多智能体系统中使用哪些智能体。
