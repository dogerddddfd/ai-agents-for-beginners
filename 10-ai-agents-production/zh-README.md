# AI 代理在生产环境中的应用：可观测性与评估

[![AI 代理在生产环境中的应用](./images/lesson-10-thumbnail.png)](https://youtu.be/l4TP6IyJxmQ?si=reGOyeqjxFevyDq9)

随着 AI 代理从实验性原型转向实际应用，理解其行为、监控其性能以及系统地评估其输出变得至关重要。

## 学习目标

完成本课程后，您将了解如何/理解：
- 代理可观测性和评估的核心概念
- 提高代理性能、降低成本和增强有效性的技术
- 系统地评估 AI 代理的内容和方法
- 在将 AI 代理部署到生产环境时如何控制成本
- 如何为使用 AutoGen 构建的代理添加工具

我们的目标是为您提供将「黑盒」代理转变为透明、可管理和可靠系统的知识。

_**注意：** 部署安全可信的 AI 代理非常重要。请同时查看[构建可信 AI 代理](./06-building-trustworthy-agents/README.md)课程。_

## 追踪和跨度

[Langfuse](https://langfuse.com/) 或 [Azure AI Foundry](https://learn.microsoft.com/en-us/azure/ai-foundry/what-is-azure-ai-foundry) 等可观测性工具通常将代理运行表示为追踪和跨度。

- **追踪**表示从开始到结束的完整代理任务（如处理用户查询）。
- **跨度**是追踪中的各个步骤（如调用语言模型或检索数据）。

![Langfuse 中的追踪树](https://langfuse.com/images/cookbook/example-autogen-evaluation/trace-tree.png)

没有可观测性，AI 代理可能感觉像一个「黑盒」——其内部状态和推理过程不透明，使得诊断问题或优化性能变得困难。有了可观测性，代理变成了「玻璃盒」，提供了构建信任和确保其按预期运行所必需的透明度。

## 为什么可观测性在生产环境中很重要

将 AI 代理过渡到生产环境会带来一系列新的挑战和要求。可观测性不再是「锦上添花」，而是一项关键能力：

*   **调试和根本原因分析**：当代理失败或产生意外输出时，可观测性工具提供了追踪，帮助精确定位错误源。这在涉及多个 LLM 调用、工具交互和条件逻辑的复杂代理中尤为重要。
*   **延迟和成本管理**：AI 代理通常依赖按令牌或按调用计费的 LLM 和其他外部 API。可观测性允许精确跟踪这些调用，帮助识别过慢或过贵的操作。这使团队能够优化提示、选择更高效的模型或重新设计工作流程，以管理运营成本并确保良好的用户体验。
*   **信任、安全和合规**：在许多应用中，确保代理行为安全和符合道德标准非常重要。可观测性提供了代理行动和决策的审计跟踪。这可用于检测和缓解提示注入、有害内容生成或个人身份信息（PII）处理不当等问题。例如，您可以查看追踪以了解代理为什么提供特定响应或使用特定工具。
*   **持续改进循环**：可观测性数据是迭代开发过程的基础。通过监控代理在现实世界中的表现，团队可以识别改进领域、收集数据以微调模型并验证变更的影响。这创建了一个反馈循环，其中在线评估的生产洞察为离线实验和改进提供信息，从而逐步提高代理性能。

## 要跟踪的关键指标

为了监控和理解代理行为，应跟踪一系列指标和信号。虽然特定指标可能因代理目的而异，但有些指标普遍重要。

以下是可观测性工具监控的一些最常见指标：

**延迟**：代理响应速度有多快？长时间等待会对用户体验产生负面影响。您应该通过追踪代理运行来测量任务和各个步骤的延迟。例如，一个所有模型调用需要 20 秒的代理可以通过使用更快的模型或并行运行模型调用来加速。

**成本**：每次代理运行的费用是多少？AI 代理依赖按令牌计费的 LLM 调用或外部 API。频繁使用工具或多个提示会迅速增加成本。例如，如果一个代理为了微小的质量改进而调用 LLM 五次，您必须评估成本是否合理，或者是否可以减少调用次数或使用更便宜的模型。实时监控还可以帮助识别意外的峰值（例如，导致 API 过度循环的错误）。

**请求错误**：代理失败了多少请求？这可能包括 API 错误或失败的工具调用。为了使您的代理在生产环境中更能抵御这些错误，您可以设置回退或重试机制。例如，如果 LLM 提供商 A 宕机，您切换到 LLM 提供商 B 作为备份。

**用户反馈**：实施直接用户评估提供了宝贵的见解。这可以包括明确的评分（👍 赞/👎 踩，⭐ 1-5 星）或文本评论。一致的负面反馈应该提醒您，这表明代理未按预期工作。

**隐式用户反馈**：即使没有明确评分，用户行为也会提供间接反馈。这可能包括立即重新表述问题、重复查询或点击重试按钮。例如，如果您看到用户反复问同一个问题，这表明代理未按预期工作。

**准确性**：代理产生正确或理想输出的频率如何？准确性定义各不相同（例如，解决问题的正确性、信息检索准确性、用户满意度）。第一步是定义您的代理成功的样子。您可以通过自动检查、评估分数或任务完成标签来跟踪准确性。例如，将追踪标记为「成功」或「失败」。

**自动评估指标**：您还可以设置自动评估。例如，您可以使用 LLM 对代理的输出进行评分，例如它是否有帮助、准确等。还有几个开源库可以帮助您评分代理的不同方面。例如，用于 RAG 代理的 [RAGAS](https://docs.ragas.io/) 或用于检测有害语言或提示注入的 [LLM Guard](https://llm-guard.com/)。

在实践中，这些指标的组合可以最好地覆盖 AI 代理的健康状况。在本章的[示例笔记本](./code_samples/10_autogen_evaluation.ipynb)中，我们将向您展示这些指标在实际示例中的样子，但首先，我们将了解典型的评估工作流程是什么样的。

## 为您的代理添加工具

要收集追踪数据，您需要为代码添加工具。目标是为代理代码添加工具，以发出可被可观测性平台捕获、处理和可视化的追踪和指标。

**OpenTelemetry (OTel)**：[OpenTelemetry](https://opentelemetry.io/) 已成为 LLM 可观测性的行业标准。它提供了一组 API、SDK 和工具，用于生成、收集和导出遥测数据。

有许多工具库可以包装现有的代理框架，并使将 OpenTelemetry 跨度导出到可观测性工具变得容易。以下是使用 [OpenLit 工具库](https://github.com/openlit/openlit)为 AutoGen 代理添加工具的示例：

```python
import openlit

openlit.init(tracer = langfuse._otel_tracer, disable_batch = True)
```

本章的[示例笔记本](./code_samples/10_autogen_evaluation.ipynb)将演示如何为您的 AutoGen 代理添加工具。

**手动创建跨度**：虽然工具库提供了良好的基线，但通常会有需要更详细或自定义信息的情况。您可以手动创建跨度以添加自定义应用逻辑。更重要的是，它们可以使用自定义属性（也称为标签或元数据）丰富自动或手动创建的跨度。这些属性可以包括特定于业务的数据、中间计算或可能对调试或分析有用的任何上下文，例如 `user_id`、`session_id` 或 `model_version`。

使用 [Langfuse Python SDK](https://langfuse.com/docs/sdk/python/sdk-v3) 手动创建追踪和跨度的示例：

```python
from langfuse import get_client
 
langfuse = get_client()
 
span = langfuse.start_span(name="my-span")
 
span.end()
```

## 代理评估

可观测性为我们提供指标，但评估是分析该数据（并执行测试）以确定 AI 代理表现如何以及如何改进的过程。换句话说，一旦您有了这些追踪和指标，您如何使用它们来评判代理并做出决策？

定期评估很重要，因为 AI 代理通常是非确定性的，并且可以进化（通过更新或漂移的模型行为）——没有评估，您不会知道您的「智能代理」是否真的做得很好，或者它是否已经退化。

AI 代理的评估有两类：**在线评估**和**离线评估**。两者都有价值，并且相互补充。我们通常从离线评估开始，因为这是部署任何代理之前的必要步骤。

### 离线评估

![Langfuse 中的数据集项](https://langfuse.com/images/cookbook/example-autogen-evaluation/example-dataset.png)

这涉及在受控环境中评估代理，通常使用测试数据集，而不是实时用户查询。您使用精心策划的数据集，其中您知道预期输出或正确行为，然后在这些数据集上运行您的代理。

例如，如果您构建了一个数学文字题代理，您可能有一个包含 100 个已知答案问题的[测试数据集](https://huggingface.co/datasets/gsm8k)。离线评估通常在开发期间进行（并且可以是 CI/CD 管道的一部分），以检查改进或防止退化。其优点是**可重复，并且由于您有真实情况，您可以获得明确的准确性指标**。您还可以模拟用户查询并根据理想答案或使用上述自动指标来衡量代理的响应。

离线评估的关键挑战是确保您的测试数据集全面且保持相关性——代理可能在固定测试集上表现良好，但在生产中遇到非常不同的查询。因此，您应该使用反映现实世界场景的新边缘情况和示例来更新测试集。混合使用小型「冒烟测试」案例和大型评估集是有用的：小型集用于快速检查，大型集用于更广泛的性能指标。

### 在线评估

![可观测性指标概述](https://langfuse.com/images/cookbook/example-autogen-evaluation/dashboard.png)

这是指在实时、真实世界环境中评估代理，即在生产中的实际使用期间。在线评估涉及监控代理在真实用户交互中的表现并持续分析结果。

例如，您可能会跟踪成功率、用户满意度分数或实时流量的其他指标。在线评估的优点是它**捕获了您在实验室环境中可能无法预料的事情**——您可以观察随时间的模型漂移（如果代理的有效性随着输入模式的转变而下降）并捕获测试数据中不存在的意外查询或情况。它提供了代理在野外行为的真实图景。

在线评估通常涉及收集上述隐式和显式用户反馈，并可能运行影子测试或 A/B 测试（其中代理的新版本与旧版本并行运行以进行比较）。挑战在于，获取实时交互的可靠标签或分数可能很棘手——您可能依赖用户反馈或下游指标（如用户是否点击了结果）。

### 结合两者

在线和离线评估不是互斥的；它们高度互补。在线监控的见解（例如，代理表现不佳的新类型用户查询）可用于增强和改进离线测试数据集。相反，在离线测试中表现良好的代理可以更自信地部署和在线监控。

事实上，许多团队采用这样的循环：

_离线评估 -> 部署 -> 在线监控 -> 收集新的失败案例 -> 添加到离线数据集 -> 完善代理 -> 重复_。

## 常见问题

当您将 AI 代理部署到生产环境时，您可能会遇到各种挑战。以下是一些常见问题及其潜在解决方案：

| **问题**    | **潜在解决方案**   |
| ------------- | ------------------ |
| AI 代理执行任务不一致 | - 完善给 AI 代理的提示；明确目标。<br>- 确定将任务分解为子任务并由多个代理处理的位置。 |
| AI 代理陷入持续循环  | - 确保您有明确的终止条款和条件，以便代理知道何时停止过程。<br>- 对于需要推理和规划的复杂任务，使用专门用于推理任务的更大模型。 |
| AI 代理工具调用表现不佳   | - 在代理系统之外测试和验证工具的输出。<br>- 完善工具的定义参数、提示和命名。  |
| 多代理系统表现不一致 | - 完善给每个代理的提示，确保它们具体且彼此不同。<br>- 使用「路由」或控制器代理构建分层系统，以确定哪个代理是正确的。 |

许多这些问题可以通过适当的可观测性更有效地识别。我们之前讨论的追踪和指标有助于精确查明代理工作流程中问题发生的位置，使调试和优化更加高效。

## 管理成本

以下是管理将 AI 代理部署到生产环境的成本的一些策略：

**使用较小的模型**：小型语言模型（SLM）可以在某些代理用例上表现良好，并将显著降低成本。如前所述，构建评估系统来确定和比较与较大模型的性能是了解 SLM 在您的用例上表现如何的最佳方法。考虑将 SLM 用于意图分类或参数提取等简单任务，同时保留较大模型用于复杂推理。

**使用路由器模型**：类似的策略是使用不同类型和大小的模型。您可以使用 LLM/SLM 或无服务器函数根据复杂性将请求路由到最适合的模型。这也将有助于降低成本，同时确保正确任务的性能。例如，将简单查询路由到更小、更快的模型，只对复杂推理任务使用昂贵的大型模型。

**缓存响应**：识别常见请求和任务，并在它们通过您的代理系统之前提供响应，是减少类似请求量的好方法。您甚至可以实现流程，使用更基本的 AI 模型来识别请求与缓存请求的相似程度。这种策略可以显著减少常见问题或常见工作流的成本。
