# 使用智能体协议（MCP、A2A 和 NLWeb）

[![智能体协议](./images/lesson-11-thumbnail.png)](https://youtu.be/X-Dh9R3Opn8)

随着 AI 智能体的使用日益增长，对确保标准化、安全性和支持开放创新的协议的需求也在增加。在本课程中，我们将介绍 3 种旨在满足这一需求的协议 - 模型上下文协议 (MCP)、智能体到智能体 (A2A) 和自然语言网络 (NLWeb)。

## 介绍

在本课程中，我们将涵盖：

• **MCP** 如何允许 AI 智能体访问外部工具和数据来完成用户任务。

• **A2A** 如何实现不同 AI 智能体之间的通信和协作。

• **NLWeb** 如何为任何网站带来自然语言界面，使 AI 智能体能够发现并与内容互动。

## 学习目标

• **识别** MCP、A2A 和 NLWeb 在 AI 智能体背景下的核心目的和优势。

• **解释** 每种协议如何促进 LLM、工具和其他智能体之间的通信和交互。

• **认识** 每种协议在构建复杂智能体系统中扮演的不同角色。

## 模型上下文协议

**模型上下文协议 (MCP)** 是一种开放标准，为应用程序提供向 LLM 提供上下文和工具的标准化方式。这为 AI 智能体提供了一个"通用适配器"，使其能够以一致的方式连接到不同的数据源和工具。

让我们看看 MCP 的组件、与直接 API 使用相比的优势，以及 AI 智能体如何使用 MCP 服务器的示例。

### MCP 核心组件

MCP 采用 **客户端-服务器架构**，核心组件包括：

• **主机 (Hosts)** 是启动与 MCP 服务器连接的 LLM 应用程序（例如像 VSCode 这样的代码编辑器）。

• **客户端 (Clients)** 是主机应用程序内的组件，与服务器保持一对一连接。

• **服务器 (Servers)** 是暴露特定功能的轻量级程序。

协议中包含三个核心原语，它们是 MCP 服务器的功能：

• **工具 (Tools)**：这些是 AI 智能体可以调用执行操作的离散操作或函数。例如，天气服务可能会提供"获取天气"工具，或者电子商务服务器可能会提供"购买产品"工具。MCP 服务器在其功能列表中公布每个工具的名称、描述和输入/输出模式。

• **资源 (Resources)**：这些是 MCP 服务器可以提供的只读数据项或文档，客户端可以根据需要检索它们。示例包括文件内容、数据库记录或日志文件。资源可以是文本（如代码或 JSON）或二进制（如图像或 PDF）。

• **提示 (Prompts)**：这些是预定义的模板，提供建议的提示，允许更复杂的工作流程。

### MCP 的优势

MCP 为 AI 智能体提供了显著的优势：

• **动态工具发现**：智能体可以从服务器动态接收可用工具列表及其功能描述。这与传统 API 形成对比，传统 API 通常需要为集成进行静态编码，这意味着任何 API 更改都需要代码更新。MCP 提供了"集成一次"的方法，从而提高了适应性。

• **跨 LLM 的互操作性**：MCP 适用于不同的 LLM，提供了切换核心模型以评估更好性能的灵活性。

• **标准化安全**：MCP 包含标准认证方法，在添加对额外 MCP 服务器的访问时提高了可扩展性。这比为各种传统 API 管理不同的密钥和认证类型更简单。

### MCP 示例

![MCP 图表](./images/mcp-diagram.png)

想象一个用户想使用由 MCP 提供支持的 AI 助手预订航班。

1. **连接**：AI 助手（MCP 客户端）连接到航空公司提供的 MCP 服务器。

2. **工具发现**：客户端询问航空公司的 MCP 服务器："你有哪些可用工具？" 服务器响应提供"搜索航班"和"预订航班"等工具。

3. **工具调用**：然后你问 AI 助手："请搜索从波特兰到檀香山的航班。" AI 助手使用其 LLM 确定需要调用"搜索航班"工具，并将相关参数（出发地、目的地）传递给 MCP 服务器。

4. **执行和响应**：MCP 服务器作为包装器，实际调用航空公司的内部预订 API。然后它接收航班信息（例如 JSON 数据）并将其发送回 AI 助手。

5. **进一步交互**：AI 助手显示航班选项。一旦你选择了航班，助手可能会调用同一 MCP 服务器上的"预订航班"工具，完成预订。

## 智能体到智能体协议 (A2A)

虽然 MCP 专注于将 LLM 连接到工具，但 **智能体到智能体 (A2A) 协议** 更进一步，实现了不同 AI 智能体之间的通信和协作。A2A 连接跨不同组织、环境和技术栈的 AI 智能体，以完成共享任务。

我们将研究 A2A 的组件和优势，以及如何在我们的旅行应用程序中应用它的示例。

### A2A 核心组件

A2A 专注于实现智能体之间的通信并让它们一起工作来完成用户的子任务。协议的每个组件都为此做出贡献：

#### 智能体卡片

类似于 MCP 服务器共享工具列表，智能体卡片包含：
- 智能体的名称。
- 它完成的**一般任务的描述**。
- **特定技能列表**及其描述，以帮助其他智能体（甚至人类用户）了解何时以及为什么要调用该智能体。
- 智能体的**当前端点 URL**
- 智能体的**版本**和**功能**，例如流式响应和推送通知。

#### 智能体执行器

智能体执行器负责**将用户聊天的上下文传递给远程智能体**，远程智能体需要这些上下文来理解需要完成的任务。在 A2A 服务器中，智能体使用自己的大型语言模型 (LLM) 来解析传入的请求并使用自己的内部工具执行任务。

#### 工件

一旦远程智能体完成了请求的任务，其工作产品就会创建为工件。工件**包含智能体工作的结果**、**已完成工作的描述**以及**通过协议发送的文本上下文**。工件发送后，与远程智能体的连接关闭，直到再次需要它。

#### 事件队列

此组件用于**处理更新和传递消息**。它在生产环境中对智能体系统特别重要，可以防止智能体之间的连接在任务完成之前关闭，尤其是当任务完成时间可能较长时。

### A2A 的优势

• **增强协作**：它使来自不同供应商和平台的智能体能够交互、共享上下文并一起工作，促进传统上断开连接的系统之间的无缝自动化。

• **模型选择灵活性**：每个 A2A 智能体可以决定使用哪个 LLM 来处理其请求，允许为每个智能体优化或微调模型，这与某些 MCP 场景中的单个 LLM 连接不同。

• **内置认证**：认证直接集成到 A2A 协议中，为智能体交互提供强大的安全框架。

### A2A 示例

![A2A 图表](./images/A2A-Diagram.png)

让我们扩展我们的旅行预订场景，但这次使用 A2A。

1. **用户向多智能体请求**：用户与"旅行智能体"A2A 客户端/智能体交互，可能会说："请为下周预订整个檀香山之旅，包括航班、酒店和租车"。

2. **旅行智能体的编排**：旅行智能体收到这个复杂的请求。它使用其 LLM 推理任务并确定需要与其他专业智能体交互。

3. **智能体间通信**：然后旅行智能体使用 A2A 协议连接到下游智能体，例如由不同公司创建的"航空公司智能体"、"酒店智能体"和"租车智能体"。

4. **委托任务执行**：旅行智能体向这些专业智能体发送特定任务（例如"查找去檀香山的航班"、"预订酒店"、"租车"）。每个这些专业智能体运行自己的 LLM 并使用自己的工具（可能是 MCP 服务器本身）执行其特定部分的预订。

5. **综合响应**：一旦所有下游智能体完成其任务，旅行智能体编译结果（航班详情、酒店确认、租车预订）并向用户发送综合的聊天式响应。

## 自然语言网络 (NLWeb)

长期以来，网站一直是用户访问互联网信息和数据的主要方式。

让我们看看 NLWeb 的不同组件、NLWeb 的优势以及通过我们的旅行应用程序了解 NLWeb 如何工作的示例。

### NLWeb 的组件

- **NLWeb 应用程序（核心服务代码）**：处理自然语言问题的系统。它连接平台的不同部分以创建响应。你可以将其视为网站自然语言功能的**引擎**。

- **NLWeb 协议**：这是与网站进行自然语言交互的**基本规则集**。它以 JSON 格式（通常使用 Schema.org）发回响应。其目的是为"AI 网络"创建一个简单的基础，就像 HTML 使在线共享文档成为可能一样。

- **MCP 服务器（模型上下文协议端点）**：每个 NLWeb 设置也作为**MCP 服务器**工作。这意味着它可以**与其他 AI 系统共享工具（如"询问"方法）和数据**。实际上，这使得网站的内容和功能可被 AI 智能体使用，使网站成为更广泛的"智能体生态系统"的一部分。

- **嵌入模型**：这些模型用于**将网站内容转换为称为向量的数字表示（嵌入）**。这些向量以计算机可以比较和搜索的方式捕获含义。它们存储在特殊数据库中，用户可以选择他们想要使用的嵌入模型。

- **向量数据库（检索机制）**：此数据库**存储网站内容的嵌入**。当有人提问时，NLWeb 检查向量数据库以快速找到最相关的信息。它提供快速的可能答案列表，按相似性排序。NLWeb 与不同的向量存储系统合作，如 Qdrant、Snowflake、Milvus、Azure AI Search 和 Elasticsearch。

### NLWeb 示例

![NLWeb](./images/nlweb-diagram.png)

再次考虑我们的旅行预订网站，但这次它由 NLWeb 提供支持。

1. **数据摄取**：旅行网站的现有产品目录（例如航班列表、酒店描述、旅游套餐）使用 Schema.org 格式化或通过 RSS 提要加载。NLWeb 的工具摄取此结构化数据，创建嵌入，并将它们存储在本地或远程向量数据库中。

2. **自然语言查询（人类）**：用户访问网站，不是通过导航菜单，而是在聊天界面中输入："为下周在檀香山找一家带游泳池的适合家庭的酒店"。

3. **NLWeb 处理**：NLWeb 应用程序收到此查询。它将查询发送到 LLM 进行理解，同时在其向量数据库中搜索相关酒店列表。

4. **准确结果**：LLM 帮助解释数据库的搜索结果，根据"适合家庭"、"游泳池"和"檀香山"等标准识别最佳匹配，然后格式化自然语言响应。至关重要的是，响应引用了网站目录中的实际酒店，避免了虚构信息。

5. **AI 智能体交互**：因为 NLWeb 作为 MCP 服务器，外部 AI 旅行智能体也可以连接到此网站的 NLWeb 实例。然后，AI 智能体可以使用 `ask` MCP 方法直接查询网站：`ask("酒店推荐的檀香山地区有素食友好的餐厅吗？")`。NLWeb 实例将处理此问题，利用其餐厅信息数据库（如果已加载），并返回结构化 JSON 响应。
